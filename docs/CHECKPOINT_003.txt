Contract (backend/src/evaluation/semantic.py):
  SemanticVerdict            verdict values verbatim from
                             semantic_evaluation_result.schema.json:
                             SUPPORTED, PARTIALLY_SUPPORTED, INSUFFICIENT, UNDETERMINED
  SemanticEvaluationRequest  frozen; grounded fields copied from the real
                             semantic_condition record + the answer text
  SemanticEvaluationResult   frozen; aligned with the result schema fields
  SemanticEvaluator          Protocol (evaluate(request)->result); NO implementation
  build_semantic_request()   resolves the REAL semantic_condition record; rejects
                             any question with no semantic_condition_id gap signal
  validate_semantic_result() treats model output as untrusted; rejects invalid
                             verdict, mismatched condition_id / question_id,
                             unknown finding, finding not authorized by the
                             semantic condition, ungrounded/overlapping elements,
                             out-of-range confidence, bad reason codes, and any
                             prohibited compliance verdict.

Semantic request example (QN-ACCESS-001-Q09 / SEMCOND-0001):

  question_id:        QN-ACCESS-001-Q09

Known limitations:
  - No semantic reasoning is implemented; SemanticEvaluator is an interface only.
  - Result objects are Python dataclasses aligned with the schema; JSON-schema
    validation of persisted results is not performed here.
  - Finding "unknown" vs "unauthorized" checks rely on the caller supplying
    known_finding_ids; without it only the authorized-finding check applies.
